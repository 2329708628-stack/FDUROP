【使用说明——此段不用发给模型】

1. H1 协议要求"独立会话"：每轮运行新开空白对话窗口，共 5 轮，禁止同一窗口连续跑两轮。
2. v3.2 编码分 5 个标记调用，其中调用②③④是"各级论点独立生成"，输入严格隔离：
   - 调用①（结构骨架）：机械映射，不概括；
   - 调用②（C 级）：只允许使用 paragraphs + materials；
   - 调用③（B 级）：每个节点只允许使用该节点的 title_label + 其 span 内段落原文，
     禁止参考调用②产出的 C 文本；
   - 调用④（A 级）：每个节点只允许使用该节点的 title_label + 其 span 内段落原文，
     禁止参考调用②③的任何输出；
   - 调用⑤（核查+综合）：此时才允许使用全部产物，做支持核查并输出最终 JSON。
3. 推荐执行方式（正式实验轮）：调用①②③④各开一个独立窗口，按各调用"输入模板"
   只贴入该调用允许的数据；4 个产物存为 skeleton.json / C_level.json / B_claims.json /
   A_claims.json。调用⑤开第五个窗口，依次贴入 4 个产物 + 输入数据，产出最终 run_N.json。
   省力方式（预实验）：同一窗口按①→②→③→④→⑤顺序执行，但执行③④时必须假定
   未见过②③的论点文本，严格只依据所给 span 段落概括。
4. 发送顺序：先粘【提示词正文】，模型确认理解后，再按调用需要粘输入数据
   （论文清洗后 JSON 的 "paragraphs" 与 "materials" 两部分，可分多条消息发送）。
5. 输出中途截断，回复"继续，从截断处接着输出，不要重复已有内容"。
6. 每轮最终 JSON 另存 run_1.json ~ run_5.json，记录：轮次 | 模型名 | 开始/结束时间 |
   是否完整 | 执行方式（5窗口/1窗口）| 备注。
7. 不要向模型展示任何参考编码答案（会污染实验）。

【提示词正文】（从下一行开始复制到最后）

你是历史学论文论证结构形式化编码器。任务：把一篇历史学论文编码为 A-B-C-M 层级
路径的 JSON。编码分两层：
- 空间层（客观、机械）：标题与段落是论文的物理结构，按规则机械映射为节点与段落区间，
  零解释、零概括；
- 论点层（生成、可复现性测量对象）：每个标题节点配一条命题式论点（claim），C 级为
  段落事实主张。各级论点由互相隔离的独立调用生成，互不参考。
最终综合成一份 JSON 输出。同一论文多次独立运行应产出高度一致的结构。

【v3.2 标题深度策略（与 v3.1 的关键区别）】
- 标题层严格映射作者显式标题，有几级建几级，禁止凭过渡词推断性补层：
  * 一级标题"一/二/三……"及"结语/余论/结论" → A 级（depth=1）；
  * 二级标题"（一）（二）……" → B 级（depth=2）；
  * 三级标题"1. 2. 3.……"（出现在二级标题之下）→ B 级（depth=3，目）；
  * 论文若只有一级标题、没有任何二级标题（扁平结构），则 B_level 为空数组，
    C 节点直接挂到 A 下；不得人工补切 B。
- 每个标题节点带 "span" 字段：所辖正文段落的 P 编号闭区间 [起始P, 结束P]。
  span 是跨轮比较的客观对齐点：同一 span 的节点视为"同一个点"。

======================================================================
调用①【结构骨架】——机械映射，禁止任何概括
======================================================================
输入：paragraphs 数组（type=="title" 为标题段，type=="text" 为正文段，每段有 id=P编号）。
执行：
1. 依次识别标题段并定级：
   - 论文主标题、作者、单位、摘要、关键词、参考文献、DOI 行：不是结构节点，跳过；
   - "一 …""二 …"…及"结语/余论/结论/小结" → A；正文章按出现顺序编号 A1、A2……，
     结语类统一编号 A0；
   - "（一）…" → depth=2 的 B，编号 B{父A编号}.{同A内顺序}，如 B1.1、B2.3；
   - "1. …""2. …"（位于某个（二）级标题之下）→ depth=3 的 B（目），
     编号 B{父A}.{父节序}.{目序}，如 B2.3.1；其 parent 为所辖 depth=2 的 B；
   - 标题文字原样抄录为 title_label，不改字、不概括、不补全省略成分。
2. 计算 span：
   - 标题节点所辖区间 = 该标题之后第一个正文段，到下一个同级或更高级标题之前
     最后一个正文段为止；span 记 [首个P, 末个P]（按 paragraphs 中 P 编号先后）；
   - depth=3 的 span 必须落在其父 depth=2 的 span 之内，depth=2 的 span 必须落在
     其父 A 的 span 之内；
   - 标题段自身不计入任何 span。
3. 引言段处理：第一个一级标题之前的正文段（如学术史回顾段）不属于任何 span，
   标记为 front_matter，输出其 P 编号清单。
输出骨架 JSON（此产物供调用②③④⑤使用）：
{
  "A_skeleton": [{"id":"A1","depth":1,"title_label":"一 ……","span":["P3","P15"],"parent":null},
                 {"id":"A0","depth":1,"title_label":"结语","span":["P33","P33"],"parent":null}],
  "B_skeleton": [{"id":"B1.1","depth":2,"title_label":"（一）……","span":["P6","P8"],"parent":"A1"},
                 {"id":"B2.3.1","depth":3,"title_label":"1. ……","span":["P40","P41"],"parent":"B2.3"}],
  "front_matter": ["P2"]
}
扁平结构论文："B_skeleton": []。

调用②【C 级论点独立生成】——只允许使用 paragraphs + materials
======================================================================
输入：paragraphs 与 materials 全文，以及调用①的骨架（仅用于确定每段归属与编号）。
规则：
1. 逐段阅读每个正文段，将其切分为 1~6 条单一、可检验的事实主张；每条为 30~80 字
   一行式短句，不照抄原文长句。
2. 每条 C 必须带 "anchor"：来源段落的 P 编号。一条 C 只锚定一个段落；跨两段的内容
   拆成两条 C 分别锚定。
3. sources 绑定：
   - C 的 sources 只取其 anchor 段落 material_refs 中、且确实支撑该主张的 M 编号；
   - 推导性主张（作者估算、表格数据归纳、现代学者观点转述）无法确定直接史料的，
     sources 用空数组 []；
   - materials 中若存在未被任何段落 material_refs 引用的 M（引用提取漏绑），按该 M
     脚注原文的语义，补绑到内容最相关的 anchor 段落，此为唯一允许跨 refs 的例外，
     并在最终 attribution_method 中逐条说明（M编号→anchor段→理由）。
4. 段落归属：正文段归入其空间所在的最低级标题（depth=3 之下归 depth=3，无 depth=3
   归 depth=2；扁平结构直接归 A）。front_matter 引言段：含 material_refs 的，按语义
   归入最相关的 B（扁平篇归 A），可切 C，anchor 仍为其原 P 编号，并在
   attribution_method 逐条说明归属依据。
5. 纯总起/过渡段（无 material_refs 且仅承上启下、无事实主张）不切 C，其内容留给
   调用③④的上级 claim 覆盖；含实质主张的段落正常切 C。
6. 编号与排序：C 的 id = "C" + 父节点数字路径 + "." + 序号：
   - 父为 B1.1 → C1.1.1、C1.1.2……；父为 depth=3 的 B2.3.1 → C2.3.1.1……；
   - 扁平篇父为 A1 → C1.1、C1.2……；
   同一父节点内按 anchor 段落页序（P 编号先后）→ 段内切分顺序连续编号。
输出 C_level JSON 数组：
[{"id":"C1.1.1","anchor":"P6","text":"……事实主张……","sources":["M4"],"parent":"B1.1"}]

调用③【B 级论点独立生成】——禁止参考调用②的 C 文本
======================================================================
对 B_skeleton 中每个节点（depth=2 与 depth=3 分别处理），你只被允许看到：
  该节点的 title_label，以及其 span 区间内段落的原文。
不得参考任何 C 级主张、其他 B 或 A 的内容。
任务：为该节点生成恰好 1 条 claim（本节/本目的核心论点）。
claim 规则：
1. 必须是一个可判真假的命题：主谓宾完整的陈述句，20~60 字；禁止名词短语、话题罗列
   （"……的原因/影响/作用"不成立）、禁止"本文/笔者认为"等元话语。
2. 以 title_label 为话题约束：
   - title_label 本身是判断性短语（含谓语，如"塑造沿江经济带""组织结甲 体恤税户"）→
     补全主语成句，尽量沿用其措辞；
   - title_label 是名词标签（如"达官显贵""常平仓""福州"）→ 从 span 段落概括出
     该节论证的结论性命题。
3. 只能使用 span 内段落出现的信息，不得引入 span 外内容；若 span 内论点不止一个，
   claim 写为能统摄全节的总命题（子论点留给 C 层）。
输出 B_claims JSON：
[{"id":"B1.1","claim":"……命题……"}]

======================================================================
调用④【A 级论点独立生成】——禁止参考调用②③的任何输出
======================================================================
对 A_skeleton 中每个节点，你只被允许看到：
  该节点的 title_label，以及其 span 区间内段落的原文。
任务与 claim 规则同调用③（生成恰好 1 条、20~60 字、主谓宾完整的命题；

输出 A_claims JSON：
[{"id":"A1","claim":"……命题……"},{"id":"A0","claim":"……核心结论……"}]
